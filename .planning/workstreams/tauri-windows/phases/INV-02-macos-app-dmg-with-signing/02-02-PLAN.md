Current `tauri.conf.json` top-level keys (Phase-1 final state, do NOT alter): `$schema`, `productName`, `version`, `identifier`, `build`, `app`, `bundle`.

After Task 02-02-02, a NEW top-level `plugins` key is added (place it AFTER `bundle`, immediately before the closing `}` of the JSON document):

```json
"plugins": {
  "updater": {
    "endpoints": [
      "https://github.com/Avi977/invisible/releases/latest/download/latest.json"
    ],
    "pubkey": "<base64-pubkey-content-from-invisible.key.pub-minus-untrusted-comment-header>"
  }
}
```

The `pubkey` field expects the BASE64-ENCODED key content only, NOT the full file with `untrusted comment:` header. Tauri 2.11's updater plugin tolerates both, but the canonical form is base64-only — this also keeps the JSON line short (~88 chars instead of two lines with a heredoc).

Tauri's `.key.pub` file format (from `cargo tauri signer generate`):
```
untrusted comment: minisign public key XXXXXXXXXXXXXXXX
<single line of base64 — this is what goes into "pubkey">
```

The `.key` (private) file format:
```
untrusted comment: minisign encrypted secret key
<line 1 base64>
<line 2 base64>
```
The PRIVATE key file goes into Infisical AS-A-WHOLE (full content including the `untrusted comment:` header) — Tauri's `signer sign` step in Phase 3 expects the whole file as the `TAURI_SIGNING_PRIVATE_KEY` env var. See 02-CONTEXT.md "Specific Ideas" paragraph for confirmation.

Important Tauri 2.x env-var detail: in Phase 3, the build will read `TAURI_SIGNING_PRIVATE_KEY` (and optionally `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`). Our Infisical secret name is `TAURI_UPDATER_PRIVATE_KEY` (per 02-CONTEXT.md LOCKED naming) — Phase 3's release.yml will map between these two names in its CI step. Do NOT rename our Infisical secret to the Tauri env-var name; Phase 3 owns that mapping.
