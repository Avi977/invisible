<threat_model>
**ASVS Level 1 baseline. Block on: high severity.**

Threats inherited from Phase 2's threat model (T1-T4) still apply. Phase 3 adds:

- **T5: GitHub Actions secret exfiltration.** A malicious or buggy step that prints `${{ secrets.TAURI_SIGNING_PRIVATE_KEY }}` to logs would expose the updater private key (T1 escalation surface). Mitigation: only the tauri-action step receives the secret via env; no `echo $TAURI_SIGNING_PRIVATE_KEY` debug step exists. GHA also automatically masks secrets in logs.
- **T6: Compromised release-pipeline action.** If `tauri-apps/tauri-action@v0` is yanked or replaced with a malicious version, the next release ships an attacker payload. Mitigation: pin to a specific commit SHA in a follow-up phase; for v0.1 the floating `@v0` tag is acceptable (the action is maintained by the Tauri team themselves).
- **T7: Accidental release.** Pushing a tag prematurely creates a release users could download. Mitigation: `draft: true` — releases require manual "Publish" click in GitHub UI before being visible to end users.
- **T8: Updater manifest poisoning** (re-stated from Phase 2's T2/T3). Mitigation: pubkey + endpoint are in version control; tauri-action signs latest.json with the private key at build time; the runtime updater verifies the signature before applying.
</threat_model>

# Plan 03-01: GitHub Actions release.yml + auto-updater
