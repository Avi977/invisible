    --- IMPORT DERIVER ---

    `def _derive_import_edges(project_root: Path, slug: str) -> tuple[list[dict], list[dict]]`:
      Returns (nodes, edges). Walks `project_root / d` for d in `_WALK_DIRS`
      (skip subtrees that don't exist — some projects may not have all three).

      For .py files:
        - Read with `path.read_text(encoding="utf-8", errors="ignore")`.
          Skip if `path.stat().st_size > _AST_FILE_MAX_BYTES`.
        - Parse with `ast.parse(source, filename=str(path))`. On `SyntaxError`,
          skip that file and continue (do NOT crash the response).
        - Walk the AST collecting `ast.Import` and `ast.ImportFrom` targets.
          For `ImportFrom`, use `node.module` (dotted module path).
        - Importer module id is the dotted path relative to project_root
          (e.g. `lib/api/projects.py` → `lib.api.projects`).
        - Add one node per unique importer id with `{id, label: basename,
          type: "module", project: slug, file_path: relpath}`.
        - For each import target that resolves to another module id inside
          the same walk (a .py file we already added a node for), add an
          edge `{from: importer_id, to: target_id, kind: "import"}`. External
          imports (stdlib, third-party) do NOT create edges and do NOT create
          target nodes.

      For .jsx files:
        - Use `_JS_IMPORT_RE` (regex, not AST) to scrape
          `import X from "<spec>"` and `import { X } from "<spec>"`.
        - Resolve relative specs (`./foo`, `../bar/baz`) against the importer's
          directory, then re-bound the resolved path to `project_root`
          (NEVER allow `..` escape — `resolved.is_relative_to(project_root)`
          gate). Bare specs (`react`, `obsidian`) are external → no edge.
        - Module id for a jsx file: dotted-path with extension stripped, e.g.
          `frontend.pages.dashboard`. Same node + edge shape as .py.

      Symlinks: iterate with `os.walk(project_root, followlinks=False)`. If
      a Path's `.is_symlink()` returns True, skip the entry entirely.

      Deduplicate edges (set of `(from, to)` tuples before emitting).

    --- GREP DERIVER ---

    `def _derive_grep_edges(project_root: Path, slug: str, module_ids: set[str]) -> tuple[list[dict], list[dict]]`:
      Returns (doc_nodes, edges). Scans only `project_root / ".planning"`.

      First pass — discover all .md files:
        - Skip if `path.stat().st_size > _GREP_MAX_FILE_BYTES`.
        - Skip if file appears binary (first 512 bytes contain `\x00`).
        - Create a doc node with `id = f"doc:{relpath_without_md}"`,
          `label = basename`, `type = "doc"`, `project = slug`,
          `file_path = relpath`.

        - Cache the read text per doc to avoid re-reading.

            `{from: doc_id, to: other_doc_id, kind: "grep"}` (skip self).
        - Deduplicate edges.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP client → daemon | Browser (typically `frontend` on `:8090`) sends an untrusted `project` query-string parameter on `GET /api/v1/relations`. This is the only attacker-controlled input crossing into the deriver. The dashboard ITSELF binds to `127.0.0.1:8765` (loopback-only IP binding controlled by `bin/invisible-dashboard` startup) — this is the actual cross-origin defense, NOT the CORS headers. `bin/invisible-dashboard:228-232` emits `Access-Control-Allow-Origin: *` globally in `end_headers()` before any handler runs; the conditional ACAO logic in `_send_json` (lines 289-296) is dead code. CORS is permissive; the loopback IP bind is what keeps non-localhost clients out. |
| daemon → filesystem | `_derive_import_edges` and `_derive_grep_edges` walk the local repo subtree. The walk root MUST be bounded to either `config.home()` (for the synthetic `"invisible"` slug) or `_safe_resolve(p["repo_path"])` (for invisible.toml `[[projects]]` entries), never derived from the URL directly, and symlinks pointing outside that root MUST NOT be followed. |
| daemon → Notion API | Outbound HTTPS to `api.notion.com` with `NOTION_TOKEN`. Untrusted response shape (the page id and title from Notion are echoed into node labels — Plan 02 frontend escapes via React text rendering, so XSS surface is closed at the consumer; here we make sure we do NOT use those values in shell, SQL, or file paths). |
| in-process cache → response | The cached graph dict is shared across requests in the same daemon process. Single-user / loopback-only, so cross-tenant leakage is not in scope. |
