## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → dashboard | Frontend (`http://127.0.0.1:8090`) makes a fetch request to the dashboard (`http://127.0.0.1:8765/api/v1/relations`). The dashboard binds to `127.0.0.1:8765` only (loopback IP binding controlled by `bin/invisible-dashboard` startup args) — this is the actual cross-origin defense. The CORS headers (`Access-Control-Allow-Origin: *` emitted globally in `end_headers()` at lines 228-232) are permissive and NOT the access-control mechanism; the loopback IP bind is. |
| API response → DOM | The dashboard returns JSON whose `nodes[].label` and `nodes[].file_path` are derived from filesystem paths and Notion data. React renders them as text nodes (default-escaped) — never as `dangerouslySetInnerHTML`, never concatenated into href / src attributes. |
| URL query string → DOM | `URLSearchParams` on this page is NOT user-controlled; the project slug is hardcoded to `"invisible"` for now. No reflected-input surface. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-02-01 | Spoofing | Foreign-origin page reading the dashboard | mitigate (inherited) | The dashboard binds to `127.0.0.1:8765` only (loopback IP binding, controlled by `bin/invisible-dashboard` startup). Non-localhost clients cannot reach the daemon at the network layer regardless of CORS headers. CORS on the dashboard is permissive (`Access-Control-Allow-Origin: *` global) — it is NOT the access-control mechanism. Plan 01-01 owns the dashboard binding; the frontend cannot weaken it. |
| T-01-02-02 | Tampering | Node labels rendered as DOM text | mitigate | React renders `{n.label}` as a text node — automatically escaped. No `dangerouslySetInnerHTML`. No interpolation into `href` / `src` attributes (the page is read-only — there are no links). Verified by inspection of the rendered jsx output. |
| T-01-02-03 | Information Disclosure | Error message leaking URL or backend internals | mitigate | `fetchRelations` catches network errors and rewraps them as `"fetchRelations: " + e.message`. `e.message` is the bare HTTP-N string for HTTP failures, or the browser's fetch error message for network failures (e.g. "Failed to fetch"). The original URL is NOT echoed into the message. The 500 body from the backend is `{"error": "internal error"}` (per Plan 01-01) — no traceback / path leakage. |

| T-01-02-05 | Information Disclosure | Browser DevTools showing the fetch URL | accept | The URL is loopback-only. Anyone with a browser session on this machine already has full filesystem access. No new exposure. |
