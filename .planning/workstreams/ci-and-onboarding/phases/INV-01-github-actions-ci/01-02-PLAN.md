<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Automation → `main` of public repo `Avi977/invisible` | `gh pr merge 3` and any `gh api branch protection` call mutate a public default branch — irreversible / high-impact; must be human-gated. |
| Third-party Action `anthropics/claude-code-security-review` (introduced by PR #3) | Runs on every PR into `main` and reads PR diffs; an upstream change to what it executes is a supply-chain risk. |
| `CLAUDE_API_KEY` repo secret (consumed by the security-review action) | A secret leaving the GitHub/Anthropic boundary; ci.yml itself never reads it, but PR #3's workflow does. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-06 | Tampering / EoP | `gh pr merge 3` writing to public `main` | mitigate | Gate the merge behind a blocking `checkpoint:human-verify` (Task 3); `autonomous: false`. The executor never auto-merges (D-06 + always_confirm_destructive). The reviewer re-confirms the SHA pin before approving. |
| T-01-07 | Tampering | `anthropics/claude-code-security-review` action ref (from PR #3) | mitigate | Keep the full-SHA pin `@0c6a49f1fa56a1d472575da86a94dbc1edb78eda` — do NOT loosen to `@main`/tag. The checkpoint instructs the reviewer to reject the merge if the pin was changed. |
| T-01-08 | Information Disclosure | `CLAUDE_API_KEY` secret handling | mitigate | Documented in BRANCH-PROTECTION.md as a manual `gh secret set`; never echoed, never committed, never placed in ci.yml. Surfaced (not silently assumed) per the phase security directive. The security action's diff-exfiltration tradeoff is recorded in PR #3's own SECURITY-REVIEW.md. |
| T-01-09 | Elevation of Privilege | branch-protection API call on `main` | accept (document-only) | D-07: the `gh api .../branches/main/protection` invocation is recorded, not executed — the owner may lack permission and changing protection on a public default branch is owner-scope. Accepted as a documented manual step. |
| T-01-SC | Tampering | npm/pip/cargo installs in this plan | mitigate | This plan installs nothing new (ruff/pytest already pinned in 01-01; both first-party PyPI). PR #3's only third-party action is SHA-pinned. No `[ASSUMED]`/`[SUS]`/`[SLOP]` packages → no auto-approve; the merge checkpoint is blocking and human-gated. |
