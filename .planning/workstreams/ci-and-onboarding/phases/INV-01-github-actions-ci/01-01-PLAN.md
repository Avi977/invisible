<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub-hosted runner → third-party Actions (`uses:`) | Each external action runs arbitrary code in the CI job; an upstream compromise or mutable tag could exfiltrate repo contents or the GITHUB_TOKEN. |
| Untrusted PR head → CI job | A PR from any branch/fork triggers the workflow; PR-controlled code/config must not be granted write scope or secret access. |
| Job token (GITHUB_TOKEN) → repo | The default token's scope is what a compromised step can use against the repo. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | `actions/checkout`, `actions/setup-python` (`uses:` in ci.yml) | mitigate | Pin both to MAJOR version tags (`@v4`, `@v5`) per D-01 — no `@main`/mutable-branch refs. (Full-SHA pinning is available as a hardening upgrade but not required for these first-party actions this phase.) |
| T-01-02 | Elevation of Privilege | ci.yml job token scope | mitigate | Top-level `permissions: { contents: read }` only. Lint/test/import-smoke need no write scope; this caps blast radius if any step is compromised. |
| T-01-03 | Information Disclosure | ci.yml secret handling | mitigate | ci.yml requires NO secrets and references none. No `echo`/`env` dumps of secrets; no `pull_request_target` with untrusted-head checkout (this workflow uses plain `pull_request` + `permissions: contents: read`). |
| T-01-04 | Tampering | `pip install ruff` / `pip install pytest` (CI dependency supply chain) | mitigate | Install ONLY ruff + pytest, each pinned to an explicit version (D-05). No project-wide requirements file, no unpinned transitive surface introduced this phase. Both packages are first-party PyPI tooling (ruff = Astral, pytest = pytest-dev) — no `[ASSUMED]`/`[SUS]` install requiring a legitimacy checkpoint. |
| T-01-05 | Denial of Service | import-smoke probing absent `api.analytics` | accept | A hard import would fail the build (DoS-by-self) when PR #8 is unmerged; D-04 soft-skips via `try/except ModuleNotFoundError`. Accepted: the absence is expected and logged, not an attacker-controlled condition. |
| T-01-SC | Tampering | npm/pip/cargo installs in this plan | mitigate | Only pinned `ruff` + `pytest` (PyPI, first-party). No `[ASSUMED]`/`[SUS]`/`[SLOP]` packages → no blocking legitimacy checkpoint required. PR #3's SHA-pinned security action is introduced in plan 01-02, not here. |
</threat_model>
